`search` returns ranked results with their URL, title and snippet. Every result
says which source found it, and every result is checked: inside the date window
you asked for, about what you asked for, and an actual item rather than a
homepage, listing or challenge page.

- Free by default: your own [SearXNG](/docs/integrations/searxng/) (optional:
  `frankensurf setup` offers to start it in Docker, and search is stronger with
  it), then
  [DuckDuckGo](/docs/integrations/duckduckgo/) and [Bing](/docs/integrations/bing/),
  plus Wikipedia, Hacker News, Stack Exchange, GitHub, arXiv, Open Library, and
  `site_watch`, which reads a site's own feeds and sitemaps.
- When a source's results fail the checks, Frankensurf climbs to the next one
  and merges what passed ([the search ladder](#the-search-ladder)).
- Paid sources [Exa](/docs/integrations/exa/), Firecrawl search,
  [Brave](/docs/integrations/brave/), [Tavily](/docs/integrations/tavily/) and
  [Parallel](/docs/integrations/parallel/) join when their keys are set and you
  allow paid tools, cheapest likely success first.
- Name a source and Frankensurf uses only that one, never a substitute.

## Narrow it down

```python
results = await web.search("film camera repair", recency="week", region="en-AU",
                           exclude_domains=["pinterest.com", "youtube.com"])
```

```bash
frankensurf search film camera repair --recency week --region en-AU \
  --exclude-domain pinterest.com --exclude-domain youtube.com
```

- `site`: only results from one domain (its subdomains too).
- `exclude_domains`: up to 200 domains that never come back. Subdomains match too (excluding `example.com` drops `news.example.com`). Engines get only the first few as `-site:` operators (`search_exclude_operators`, default 3); the full list is enforced on the results, and the search asks for extra results so the limit is still met.
- `recency`: `day`, `week`, `month` or `year`.
- `region`: language and country, like `en-AU` or `de`.

Each source applies what it can natively: SearXNG `time_range`, DuckDuckGo
`df` and `kl`, Bing's date filters and `cc`, Exa and Tavily domain and date
filters, Brave `freshness`, and `site:`/`-site:` operators where an engine
reads them. Then every result list is filtered again, so an excluded domain
never comes back from any source, and dated results older than the window are
dropped. `receipt.search_options.filtered` counts what went, including how
many results had no date to check.

## Kinds of search

`vertical` picks the kind of source. Automatic fallback stays inside it.

| `vertical` | Source | Notes |
| --- | --- | --- |
| `web` (default) | SearXNG, DuckDuckGo, Bing, plus paid sources when allowed | |
| `news` | Bing News RSS | Publisher in `extra.publisher`, dates on every item |
| `reference` | Wikipedia API | In the `region` language (`de` searches de.wikipedia.org) |
| `discussions` | Hacker News (Algolia API) | `extra.points`, `extra.comments`, `extra.discussion_url` |
| `qa` | Stack Exchange API | Stack Overflow by default; any Stack Exchange site by name via `engine_config={"engines": "superuser"}` |
| `code` | GitHub API | Repositories; `recency` means pushed recently. `extra.stars` |
| `papers` | arXiv API | |
| `books` | Open Library | |

All of these are official, keyless public APIs.

## Local search

Search works with nothing installed. A local SearXNG makes it stronger, and
`frankensurf setup` offers to start one if Docker is running: it asks first
(default no, never in scripts or CI), `--search` says yes ahead of time and
`--no-search` skips the question. `frankensurf search-engine start`, `stop` and
`status` do the same later. See [SearXNG](/docs/integrations/searxng/).

When an automatic search ran without it because nothing answered on
`127.0.0.1:8088`, the receipt says why results may be thinner:

```json
"search_routing": {
  "local_search": {
    "status": "not_running",
    "note": "Local search (SearXNG) was not running, so this search used other sources and may be thinner. Start it with: frankensurf search-engine start",
    "start_with": "frankensurf search-engine start"
  }
}
```

The field is absent when SearXNG answered, when you named a source, and when
you pointed at your own search URL.

## The search ladder

An automatic search (no `source`) does not stop at the first source that answers.
It checks every result set the way a read checks a page, and climbs to the next
source until a set is good: at least `min(3, limit)` results (`search_good_results`)
that pass.

A result fails when it:

- is provably outside the `recency` window (its own date, a date the snippet
  leads with, "3 days ago", or a `/2026/10/12/` URL path; an unknown date is not a
  failure, it only ranks below dated in-window results);
- shares no key term with the query (stopwords and words like *news*, *latest*,
  *this week* don't count);
- is a homepage, search page, tag listing or challenge page, when the query asks
  for specific items (a path that ends in an index word such as `/newsroom/`,
  `/changelog/`, `/press-releases/` or `/c/announcements/22`, or an aggregator's
  `/news/<company>`, is a listing; a path with a title slug is not);
- repeats another result's page.

With a `recency` window, results that carry no date are not left to guess at:
the pages of up to `search_date_reads` (default 6) undated results that would make
the top are read at once over plain http (`search_date_read_timeout_seconds`,
default 5; no paid tools, the normal per-origin pacing), and the publication date
in the page's own metadata (`article:published_time`, JSON-LD `datePublished`,
`<time datetime>`; never a modified date) is set as the result's `published`
with `date_source: "page"`. Results now provably outside the window drop out;
results that still have no date stay, ranked below verified ones, and count for
at most half of `search_good_results`, so the ladder keeps climbing instead of
settling for undated filler. `receipt.search_checks.date_reads` reports
`tried`, `dated`, `dropped`, `latency_ms` and `cost_usd`. `search_date_reads: 0`
turns this off.

When any result's date is verified inside the window, results whose date could
not be verified leave `results` and come back apart as `unverified_results`: the
answer holds only what is known to be fresh, and nothing is hidden.
`search_hold_undated: false` mixes them back in, ranked last. So that holding
results back does not leave the answer short, a good windowed answer with fewer
verified results than `limit` asks up to `search_fill_rungs` (default 2) more free
sources and merges what passes.

Weak sets are not wasted: passing results from earlier sources are carried up,
merged and deduplicated, and the search ends as soon as the sources together have
enough. Paid sources join only with `allow_paid_fallbacks`, after
`search_paid_after_weak` free sources (default 2) came back weak, cheapest
likely success first. A free source with no answer after
`search_hedge_after_seconds` (default 3) is raced by the next free one; the first
set that passes wins. `search_max_seconds` and `search_max_sources` cap the climb.

FrankenSurf remembers, per kind of query (vertical, recency or not, site filter
or not), which source passed the checks and tries it first next time
(`search_learned_routing`, stored in `search-stats.json` in the state directory).

Every result carries `check` (`passed`, `in_window`, `on_query`, `published`,
`date_source`, `kind`), and the receipt says what happened:

```json
{
  "search_ladder": {"enabled": true, "query_type": "news|recent|open",
                    "order": ["bing_news_rss", "duckduckgo_html"],
                    "winner": "merged", "stopped": "good", "hedged": []},
  "search_checks": {"verdict": "good", "need": 3, "passed": 3,
                    "reasons": {"off_query": 2, "out_of_window": 1},
                    "unknown_dates": 1,
                    "results": [{"url": "https://example.com/2026/10/11/story", "source": "bing_news_rss",
                                 "in_window": true, "on_query": true,
                                 "published": "2026-10-11T23:59:59Z", "date_source": "url", "kind": "item"}]},
  "search_attempts": [{"source": "bing_news_rss", "status": "observed", "count": 10, "passed": 2,
                       "check": "weak", "cost_usd": 0, "latency_ms": 412}]
}
```

`search_ladder: false` restores the first-answer behaviour. An explicit `source`
is asked once and its results are annotated but never dropped.

## Merge mode

`mode="merge"` asks every eligible source in the vertical at once (up to
`search_merge_sources`, default 4) and fuses their lists by reciprocal rank.
Duplicate pages (`www.`, trailing slashes and tracking parameters aside) merge
into one result that lists every engine that found it, with `fusion.sources`
giving each engine's rank. One blocked engine costs nothing, and a page found
by several engines rises. `receipt.search_merge` reports each source.

```python
results = await web.search("film camera repair sydney", mode="merge")
```

## Options

| Option | Default | Description |
| --- | --- | --- |
| `source` | automatic | One source only, by name (see the tables above). |
| `limit` | `10` | Number of results. |
| `site`, `exclude_domains`, `recency`, `region` | none | See above. |
| `vertical` | `web` | The kind of source. |
| `mode` | `fallback` | `merge` to ask every eligible source at once. |
| `search_source_prefer` | none | Try these sources first. |
| `search_source_allow` | all | Only these sources may run. |
| `search_source_timeout_seconds` | `8` | Time per source. |
| `allow_paid_fallbacks` | `false` | Let the paid sources join. |

  A search hit is an indexed candidate, not proof the page is live. Read it to
  find out.
